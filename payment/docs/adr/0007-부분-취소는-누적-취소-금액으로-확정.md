# 0007. 부분 취소 결과는 결제사의 누적 취소 금액으로 확정한다

## 2026-10-07 (적용 중)

### 배경

- 부분 취소 후 결제사 결제 상태는 `PARTIAL_CANCELLED`라, 상태(`CANCELLED`)로는 취소 반영을 판정할 수 없다
- 취소 응답의 `cancellation.status`가 `REQUESTED`(PG사 처리 중)일 수 있다
- PortOne 취소 요청에 `currentCancellableAmount`(직전 취소 가능 잔액)를 넣으면 잔액이 일치할 때만 취소된다

### 결정

- 요청: `currentCancellableAmount` = 이번 요청 직전 잔액, 멱등키 = `cancellationId`. 잔액 조건은 기한 없는 이중 환불 방어(멱등키는 3시간 뒤 만료)
- 요청 응답: `SUCCEEDED` → 성공, `FAILED`·4xx → 실패, `REQUESTED`·5xx·타임아웃 → `PENDING` 유지 후 폴링. `REQUESTED`를 성공으로 보면 PG사가 나중에 거절했을 때 잘못 통지한다
- 폴링: 결제사 `amount.cancelled`가 예상 누적 취소(성공한 취소 합계 + 확인 중인 건)와 일치하면 성공, 아니면 한도까지 대기 후 `UNKNOWN`. 미확정 취소가 결제당 하나(0004)라 금액 증가만으로 판정된다
- 누적 금액은 "처리 중"과 "거절됨"을 구분하지 못해, 폴링에서는 실패를 확정하지 않는다
- 같은 `cancellationId`가 다시 오면 결제사를 부르지 않고 넘긴다
- 결제사 호출 전 가드(결제 미완료, 금액 초과, 다른 취소 진행 중)에 걸리면 `FAILED` 취소 건으로 기록하고 취소 실패 이벤트를 발행한다. 예외로만 끝내면 결과가 전달되지 않고, 기록이 있어야 재수신이 걸러진다

### 트레이드오프

- 얻는 것: 결제사 취소 내역 배열을 우리 건과 짝짓지 않아도 된다
- 감수하는 것: 폴링 중 결제사가 거절한 취소는 실패가 아니라 `UNKNOWN`으로 끝나 사람이 확정한다
