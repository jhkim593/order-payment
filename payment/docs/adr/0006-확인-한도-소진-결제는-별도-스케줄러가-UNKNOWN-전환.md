# 0006. 확인 한도를 다 쓴 결제는 별도 스케줄러가 UNKNOWN으로 전환한다

## 2026-10-05 (적용 중)

### 배경

- 기존에는 4번째 확인 직후 같은 흐름에서 `UNKNOWN`으로 저장했다
- 확인 횟수 선점은 이미 커밋된 뒤라, 이 저장이 실패하면 `PENDING`·4회로 남고 다시 잡히지 않는다
- `UNKNOWN`이 관리자 알림 경로라, 돈이 나갔을 수 있는 결제가 알림 없이 묻힌다

### 결정

- 확인 흐름에서는 `UNKNOWN` 판정을 하지 않는다
- 별도 스케줄러가 매 사이클 확인을 다 쓴 미확정 결제를 `UNKNOWN`(취소는 `CANCEL_UNKNOWN`)으로 전환하고 관리자에게 알린다. 실패해도 다음 사이클에 같은 조회로 다시 잡힌다
- 선점(조건부 UPDATE)은 쓰지 않는다. 결제사를 부르지 않는 멱등 작업이라 겹쳐도 결과가 같다
- `checked_at < now - 10초` 조건으로 진행 중인 4번째 확인이 저장한 결과를 덮어쓰지 않게 한다

```
status = :status AND check_count >= CHECK_LIMIT AND checked_at < now - CHECK_INTERVAL_SECONDS
```

### 트레이드오프

- 얻는 것: 전환 지점이 한 곳이고 별도 복구 장치가 필요 없다
- 감수하는 것: `UNKNOWN` 전환이 최대 한 사이클(10초) 늦어진다
- 감수하는 것: 인스턴스가 겹치면 알림이 두 번 나갈 수 있다
- 감수하는 것: 결제사 상태 조회 타임아웃을 10초 미만으로 유지해야 한다
