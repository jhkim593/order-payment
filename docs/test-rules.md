# 테스트 규칙

테스트는 스펙 문서를 기반으로 작성한다.

테스트 메서드명은 의도가 드러나게 한글로 작성해도 된다.

## 테스트 대역

가능하면 Mockito 대신 Fake를 쓴다. Mockito를 금지하는 것은 아니다.

- Fake는 포트 인터페이스를 메모리로 구현한 클래스다. 테스트 소스의 `fake` 패키지에 두고 여러 테스트가 함께 쓴다.
- 호출 인자를 검증(`verify`)하기보다, Fake를 거친 뒤의 **결과 상태**를 검증한다. 구현이 바뀌어도 동작이 같으면 테스트가 깨지지 않는다.
- 시간에 따라 달라지는 동작은 `Clock`을 주입받아 테스트에서 시간을 움직인다.
- Mockito가 나은 경우: 예외 상황을 한 번만 흉내 낼 때, Fake로 만들기엔 인터페이스가 지나치게 클 때.
