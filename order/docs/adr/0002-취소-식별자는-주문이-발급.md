# 0002. 취소 식별자를 주문이 발급하고 결과까지 따라다니게 한다

## 2026-10-04 (적용 중)

### 배경

- 부분 취소에서는 한 주문에 취소가 N건 생긴다
- 결제 이벤트 페이로드가 `(paymentId, orderId)`뿐이라 어느 취소 건의 결과인지 구분할 수 없다

### 결정

- 주문이 `cancellationId`(Snowflake)를 발급하고, 그 값이 전 구간을 따라다닌다
- 아웃박스 `eventId`를 쓰지 않는다. 주문이 취소 건 추적용 id를 어차피 만들어야 해 하나로 합친다
- `OrderCancelEventPayload`에 `amount`를 싣는다. 금액 계산은 주문의 책임이고 결제는 숫자만 받는다
- 중복 방지: 요청 중복은 주문의 취소 수량 가드, 전송 중복은 결제의 `cancellation_id` PK, 호출 중복은 결제사 멱등키

```
order_cancellation.cancellation_id
  → ORDER_CANCEL 페이로드 → payment_cancellation PK
  → 결제사 멱등키 → 결과 이벤트 페이로드
```

### 트레이드오프

- 얻는 것: 업무 식별자 하나로 요청부터 결과까지 추적된다
- 감수하는 것: 취소 관련 이벤트 페이로드 3종에 `cancellationId`가 추가된다
