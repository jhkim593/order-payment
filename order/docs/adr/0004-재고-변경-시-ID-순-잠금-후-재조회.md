# 0004. 재고 변경 시 상품을 ID 순으로 잠그고, 잠근 뒤 최신 값으로 다시 읽는다

## 2026-10-07 (적용 중)

### 배경

- 재고는 도메인 메서드로 바꾸고 더티 체킹으로 반영한다. 최종 값을 `UPDATE`하므로 출발점이 최신 값이어야 한다
- 결제 실패·취소 성공 경로는 주문을 `find`(상품 fetch join)로 먼저 읽어 상품이 락 없이 1차 캐시에 올라온다
- 이후 `FOR UPDATE`로 다시 조회해도 락만 걸리고 기존 객체가 돌아와, 그사이 바뀐 재고를 덮어쓴다

```
T1: find(주문) → 상품 A stock=10 (락 없음)
T2: A 10 → 8, 커밋
T1: FOR UPDATE → 객체는 10 그대로 → +3 → UPDATE stock=13 (정답 11)
```

### 결정

- `ProductRepository.findAllForUpdate(ids)`는 `ORDER BY product_id ... FOR UPDATE` 한 쿼리로 잠근다. 같은 순서로 잠가 데드락을 막는다
- 잠근 뒤 각 상품을 `EntityManager.refresh`로 다시 읽는다. 호출하는 쪽이 어떻게 읽었든 최신 값에서 출발한다
- `refresh`는 어댑터(`ProductDBRepository`) 안에만 둔다. 서비스는 `EntityManager`를 모른다

### 트레이드오프

- 얻는 것: `find`의 fetch join을 바꾸지 않고, 호출 순서 전제도 생기지 않는다
- 감수하는 것: 재고를 바꿀 때 상품 수만큼 `SELECT`가 더 나간다
- 감수하는 것: `refresh`가 미반영 변경을 버리므로, 잠그기 전에 같은 상품을 메모리에서 수정하지 않는다
